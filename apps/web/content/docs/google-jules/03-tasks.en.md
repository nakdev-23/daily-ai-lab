# Task — assigning work to Jules 📋

> Adapted from the official documentation at [jules.google](https://jules.google/docs)

## 🔄 The task lifecycle

1. **You write the task** (in plain language)
2. **Jules plans** — shows the steps it will take
3. **Approve** — you review the plan and let it start
4. **Get to work** — Jules fixes the code in the VM, runs tests
5. **Open a PR** — sends the work for review on GitHub
6. **Review/request changes** — you comment, ask for more changes, or merge

## ✍️ Writing good tasks

| Do | Avoid |
|---|---|
| State a clear goal + success criteria | "Make it better" |
| Point to the relevant files/parts | Commanding the whole project broadly |
| Break a big job into subtasks | Cramming several things into one task |

## 👀 Review the Pull Request

- Look at the **diff** to see what changes
- Read the summary Jules wrote
- Comment to request changes, or approve + merge
- It works on a separate branch, so it's safe for main

## 💡 Tips

- Review the plan before approving, to avoid lots of rework later
- Assign several tasks in parallel (Jules works in the background)
